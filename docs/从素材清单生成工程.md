# 从素材清单生成工程

**场景**:同一套动效要铺到 3 个品牌 × 3 个方案 = 9 个合成,手点不可能。
**结论**:`manifest.json`(数据) → Python 生成 `.jsx`(逻辑) → AE 跑成 `.aep`(产物)。

## 1 为什么要多这一层

| 直接写 jsx | 生成器 |
|---|---|
| 9 个合成 × 10 个图层 × 4 条表达式 = 360 段手写字符串 | 模板写一次,数据填 9 次 |
| 改一个位移量要全文替换 | 改 `meta.motion.iconDy` |
| 数据与代码混在一起,没法审 | `manifest.json` 可单独 review |

而且 **AE 的 ExtendScript 没有 `JSON.parse`**,清单只能变成 **JS 字面量**内联。
生成器在 Python 侧拼好字符串再写进去,比在 jsx 里二次拼更可控(也更容易做"逐字一致"校验)。

## 2 三层结构

```
manifest.json   数据:合成规格 / 背景 / 路径 / 每个图层(cx,cy,role,idx) / 抽帧时间
     ↓ build_aep.py
build_<名>.jsx  逻辑:公共函数 + DATA 字面量 + 循环建层 + 体检 + 抽帧 + 存盘
     ↓ run_ae.ps1
<名>.aep        产物 + ae_render/*.png
```

## 3 合成的固定结构

```
参数控制(null 对象,置顶,滑块条数由 meta.sliders 决定)
图层 1..n(PNG footage,Position=(cx,cy),每条属性一段表达式,可选高斯模糊)
BG(solid #0F0F11,置底,locked)
```

★ **参数控制必须是 null 对象,不能是 solid** —— solid 是不透明黑层,置顶后把整幅画面盖住,
而**日志完全正常**:只有抽帧能看出来(bbox 退化成整帧 `(0,0,2048,1152)`、`pixels≈2,358,478`)。

为什么这个顺序:

- **参数控制置顶**:表达式统一用 `thisComp.layer("参数控制")` 找它,名字必须稳定,不能被图层重名顶掉;
- **BG 置底 + 锁定**:抽帧/审阅不会误选,也不会被表达式带着动;
- **图层顺序 = 叠放顺序**:先加的在下,所以"图标在最上"就要最后加。

## 4 role 决定读哪组滑块

| role | 时长 / 延迟 | 错位 | 用在 |
|---|---|---|---|
| `icon` | 图标时长 / 图标延迟 | — | 品牌图标 |
| `logo` | 文字时长 / 文字延迟 | 文字错位 | 逐字 Logo |
| `tag` | 副标题时长 / 副标题延迟 | 副标题错位 | 副标题逐字 |
| `logo_full` | Logo整体时长 / Logo整体延迟 | — | 整体 Logo(不动内部字) |

`idx` 是**同组内的序号**(0 起):错位 = `S + idx * 错位ms`;方案 `s3` 里还用它决定左右方向。

## 5 生成物必须包含的四段

1. **路径常量 + `DATA`**:日志、抽帧目录、`.aep`、素材目录
2. **公共函数**:`L()` / `hexToRgb` / `importPng` / `setT` / `addBlur`
3. **每层**:import → 命名 → `Position.setValue([cx,cy])` → 逐条挂表达式 → 可选模糊
4. **收尾**:表达式体检 → 抽帧(带 sleep + exists)→ `save` → `L("DONE")` → `quit`

第 4 段里的 `scanExpr` 递归遍历属性树,把 `expressionError` 非空的打到日志。
**这是唯一能自动化发现"表达式写错"的手段** —— AE 不会弹错,只是属性值变红。

## 7 坑

| 坑 | 现象 | 修法 |
|---|---|---|
| 迭代根节点 | `KeyError: 'icon'` | 根上是 `meta`,要迭代 `comps` |
| 缓动源码两份 | 改了一处另一处没改 | `--check-ease` 逐字比对 |
| 表达式里带 `//` | 后半段被注释 | 不写行注释 |
| 图层名重复 | `thisComp.layer("参数控制")` 取到别的层 | 参数控制名唯一,禁止重名 |
| 素材缺文件 | `MISS xxx.png` 后图层不存在 | 先跑 `exists` 自查,清单路径相对 `asset_dir` |
| 参数控制用 solid | 抽帧整帧都是黑,bbox=`(0,0,W,H)` | 改 `addNull`(solid 不透明) |
| 体检误报 | 每条 `EXPR_ERR <合成名> :: undefined` | `expressionError` 在 `CompItem` 上是 `undefined`,判 `typeof err === "string"` |

## 8 和 `vector-extract` 的接缝

`vector-extract` 输出 `elements.json`(`{elements:[{file,w,h,cx,cy}]}`),
`comp-builder` 吃的是 `manifest.json`(`{comps:[{layers:[...]}]}`)。两者**故意分开**:

- `elements.json` 是**素材事实**(尺寸与中心),由设计稿决定;
- `manifest.json` 是**编排意图**(哪个元素进哪个合成、什么 role、什么方案),由动效决定。

中间那一步"挑元素、给 role、拼合成"是**人的决策**,不该自动化。
接缝写法:`layers[]` 里的 `file` 直接抄 `elements[].file`, `cx/cy` 直接抄过来。
