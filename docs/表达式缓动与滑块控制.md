# 表达式缓动与滑块控制

**场景**:一整套入场动画要能"一次做好、之后随手调时长/延迟/错位",且不能因为 AE 的 API 缺陷崩掉。
**结论**:关键帧缓动不可用 ⇒ 用表达式里的 cubic-bezier 反解 + 一组滑块。

## 1 为什么放弃关键帧缓动

实测三条,全部指向"不可用":

| 属性 | 调用 | 结果 |
|---|---|---|
| Position | `setTemporalEaseAtKey(1, [ease], [ease])` | 报 `由于参数 2,无法调用 ... 值数组没有 1 元素` |
| Scale | 同上(2 个 ease) | **AE 进程直接消失**,`try/catch` 接不住 |
| Position | 退成 1 个 ease | 过校验,但**采样/渲染阶段崩** |

第 3 条最坑:参数校验通过、调用返回、日志正常,崩在**几秒后**;当时以为是 `saveFrameToPng` 的问题。

> 判据:只要"多维亚属性 + ease"的组合出现,先假设不可用。要看缓动对不对,就**抽帧看**,别信 API 返回值。

## 2 表达式方案

```javascript
var C = thisComp.layer("参数控制");
var D = Math.max(0.05, C.effect("图标时长")(1) / 1000);   // ms -> s
var S = C.effect("图标延迟")(1) / 1000;
var u = Math.min(1, Math.max(0, (time - S) / D));         // 归一化进度
var f = cb(u, 0.16, 1, 0.3, 1);                           // CSS cubic-bezier(0.16,1,0.3,1)
[value[0], value[1] + 40.96 - 40.96 * f];                 // 从 +40.96px 处上浮到基准位置
```

三个要点:

1. **`u` 必须 clamp**。缺了它,延迟到来前 `u<0`、动画结束后 `u>1`,位移会先反向跳再冲过头。
2. **`value` 是图层摆好的位置**。位移写 `value + dy - dy*f`,**不要写绝对坐标** —— 否则改画布尺寸/位置全废。
3. **`Math.max(0.05, D)`** 防 0:滑块拨到 0 时 `(time-S)/0` 会得到 `Infinity/NaN`,整层消失。

## 3 cubic-bezier 反解

CSS 的 `cubic-bezier(x1,y1,x2,y2)` 给的是**控制点**,而表达式需要的是"给定时间 t 求进度 y"。
中间缺一步:**由 x 反解参数 s**。

```
x(s) = 3(1-s)²s·x1 + 3(1-s)s²·x2 + s³
y(s) = 3(1-s)²s·y1 + 3(1-s)s²·y2 + s³
```

`s ∈ [0,1]` 上 `x(s)` 单调递增 ⇒ **二分 20 次**足够(精度 2⁻²⁰ ≈ 1e-6,30fps 一帧是 33ms)。

```javascript
function cb(t,a,b,c,d){
  var lo=0,hi=1,s=t,i,x;
  for(i=0;i<20;i++){
    x=bx(s,a,c);
    if(x<t){lo=s;}else{hi=s;}
    s=(lo+hi)/2;
  }
  return by(s,b,d);
}
```

注意参数顺序是 `cb(t, x1, y1, x2, y2)` —— 写成 `cb(t,x1,x2,y1,y2)` 时**曲线形状会完全不同但不报错**。

四条曲线的实测值(`scripts/expression-tween/README.md` 有完整的表):

| 曲线 | t=0.25 | t=0.5 | t=0.75 |
|---|---|---|---|
| `out` `(0.16,1,0.3,1)` | 0.8256 | 0.9718 | 0.9977 |
| `back` `(0.34,1.56,0.64,1)` | 0.8163 | **1.0874** | 1.0596 |
| `inOut` `(0.65,0,0.35,1)` | 0.0708 | 0.5 | 0.9292 |

`back` 的 1.0874 > 1 就是**超调**,用来做缩放的轻微回弹。

## 4 参数控制图层

一个 solid,置顶,挂 10 个滑块:

| 滑块 | 默认(ms) | 作用 |
|---|---|---|
| 图标时长 / 图标延迟 | 500 / 0 | 图标入场 |
| 文字时长 / 文字延迟 / 文字错位 | 500 / 0 / 0 | 逐字 Logo;错位 = 每个字多等 N ms |
| 副标题时长 / 副标题延迟 / 副标题错位 | 400 / 400 / 0 | 副标题逐字 |
| Logo整体时长 / Logo整体延迟 | 1000 / 0 | 整体 Logo |

创建:

```javascript
var ctl = comp.layers.addSolid([0,0,0], "参数控制", w, h, 1, dur);
ctl.moveToBeginning();
var fx = ctl.property("ADBE Effect Parade").addProperty("ADBE Slider Control");
fx.name = "图标时长";
fx.property(1).setValue(500);
```

读取:**按索引** `effect(1)`。

> ★ 中文界面下的两种名字情况,别混:
> - **默认英文名**(`Slider`、`Blurriness`)**取不到** ⇒ `property("Slider")` 返回 `null`;
> - **自己用脚本命名的中文名**(`fx.name = "图标时长"`)**可以**在表达式里 `effect("图标时长")(1)` 取到。
>
> 所以:读**别人的**效果参数用索引,读**自己命名的**滑块用名字。

错位怎么算:

```javascript
S += idx * C.effect("文字错位")(1) / 1000;   // idx = 第几个字(0 起)
```

### 6.1 采样对表(最硬的一条)

抽帧只能证明"在动";**"是不是按这条曲线在动"只能靠读表达式求值后的值**。

```powershell
run_ae.ps1 -Jsx probe_curve.jsx -Log curve_probe.log     # 只读:打开 aep、采样、退出
python compare_curve.py curve_probe.log --profile s5v2
```

做法上有三个刻意的选择:

1. **基准取末帧,而不是 cy**:只比"还差多少像素"(`当前 y − 静止 y`),就不需要外部常数,
   也不会把"整体摆偏"误判成"曲线错";
2. **先检查末两帧相等**:末帧是基准,动画没停就不能用;
3. **单独查分段落地**:`u≥55%` 之后 `opacity=100、blur=0` 而位移**仍有余量**(`5.22px`)——
   这条能区分"真分段 `cb(min(1,u/0.55))`"和"整体乘个系数"的假实现。

## 7 坑

| 坑 | 后果 | 修法 |
|---|---|---|
| 表达式里写 `//` 注释 | 拼接成一行后**后半段全被注释** | 只写 `/* */` 或干脆不写 |
| `cb` 参数顺序错 | 曲线形状错但不报错 | 固定 `cb(t,x1,y1,x2,y2)` |
| 忘 clamp `u` | 延迟前反向跳、结束后冲过头 | `Math.min(1, Math.max(0, ...))` |
| 滑块直接写秒 | 交付方理解成帧 | 一律 ms,表达式 `/1000` |
| 表达式写绝对坐标 | 改画布尺寸后全偏 | 用 `value` 作基准 |
| 一个表达式调用外部函数 | 报"未定义" | 缓动源码必须**内联进字符串** |
