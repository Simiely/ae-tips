# 抽帧核验

**场景**:AE 无人值守跑完一批合成,要证明"每张都对",而不是打开工程用眼睛看。
**结论**:`saveFrameToPng` 抽帧 → 逐张算**非背景 bbox / 像素数** → 与设计稿包围盒比对。

## 1 抽帧

```javascript
comp.openInViewer();
comp.saveFrameToPng(t, new File(fn));
$.sleep(900);
L("frame " + fn + " exists=" + (new File(fn)).exists);
```

**这是异步操作**。首轮 27 帧,"日志全成功、磁盘 0 个文件" —— 根因就是投递后立刻
`app.quit()`,写入队列被进程退出吞掉。加 `sleep` 后 27/27 落盘,结尾再 `sleep 2500` 兜底。

## 2 四条判据

| # | 判据 | 失败意味着 |
|---|---|---|
| 0 | 每张 `pixels > 0` | 抽帧没落盘 / 图层全透明(alpha 反解失败) |
| 1 | 同一合成像素数随时序**单调不减** | 入场方向反了 / 元素中途消失(**回弹方案别开**) |
| 2 | 末帧 bbox 在期望 ±4px 内 | 位置 / 尺寸 / 素材边距错 |
| 3 | 改滑块后同一时间点 bbox 必须变 | 表达式没读到滑块 / 滑块名错 |

判据 1 与 2 是**互相独立**的:1 证明"在动",2 证明"停在正确的地方"。只做 2 会漏掉"根本没动"。

## 3 为什么不用 md5 判"图一样"

PNG 文件里含时间戳类块 ⇒ **md5 不同、字节数可能完全相同**。
早期用 md5 判"变体是否生效",5 个变体全报"生效"而每个文件字节数一模一样 —— 假阳性。

⇒ 判"两张图一样"**必须比像素**;判"有没有变化"也**比像素**。

## 4 实测:9 个合成 / 27 帧

```
c7   0.000   2048x1152   (787, 488, 1250, 613)     24324
c7   0.120   2048x1152   (787, 477, 1250, 603)     24554
c7   0.280   2048x1152   (787, 477, 1258, 678)     27419
FAIL=0  合成数=9  帧数=27
```

末帧 bbox 与设计稿:

| 合成 | bbox | 与 `logo_full` 中心的差 |
|---|---|---|
| QQ音乐 | `792–1256 / 477–677` | 1px |
| 全民K歌 | `796–1256 / 484–681` | 1px |
| 懒人听书 | `787–1257 / 477–677` | 2px |

> bbox 差 1–2px 是**字形左右留白**造成的,不是位置错。判据给 ±4px 就是为这个。

## 5 滑块生效的证明

同一合成、同一时间点 `t=0.12s`,只改「图标时长」:

| 滑块 | 图标顶边 |
|---|---|
| 500ms | `486px` |
| 1000ms | `497px` |

差 11px ⇒ 动画被"拉长",同一时刻还停得更靠上 ⇒ 滑块确实进了表达式。

> 反面判据同样重要:**如果值不变**,说明表达式读不到滑块(名字/索引错),而不是"滑块没做界面"。

## 6 联系表

`verify_frames.py --contact contact.png` 会按 `c<N>` 一行、时间从左到右拼图。

- 联系表**只给人看**,不进判据;
- 尺寸 `340×191` 一格的九行三列,足以发现"某个字没出现""整体偏左"这类结构性错误;
- 判据仍以数字为准。

## 7 坑

| 坑 | 后果 | 修法 |
|---|---|---|
| 不等写盘 | 日志成功、文件不在 | `sleep` + `exists` |
| `T` 编码成抽帧下标 | 读成 "0.01 秒",歧义 | 用**毫秒** |
| 阈值太低 | 背景噪点算成内容 | 默认 6–8 |
| 背景色凭眼睛填 | 差 1 个通道就把背景判成内容 | 从 manifest 取 |
| 只做末帧 | 漏"根本没动" | 加单调性判据 |
