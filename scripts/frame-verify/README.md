# frame-verify · 抽帧核验

把 `ae_render/` 里的 PNG 逐张量成数字:**非背景包围盒 / 像素数 / 与期望包围盒的差**。
"做对了"必须是读数,不是"看起来像"。

## 用法

```bash
python verify_frames.py <render_dir> --bg 0F0F11
python verify_frames.py <render_dir> --bg 0F0F11 --expect expects.json --contact contact.png
```

`expects.json`(键是**文件名前缀** `c<N>`,与合成顺序对应):

```json
{
  "c1": { "name": "QQ音乐_方案1", "bbox": [792, 477, 1256, 677], "tol": 4 },
  "c2": { "name": "全民K歌_方案1", "bbox": [796, 484, 1256, 681], "tol": 4 }
}
```

## 文件名约定

`c<N>_t<T>.png`:

- `N` = 合成序号(**从 1 起**),对应生成器里 `comps` 的顺序;
- `T` = **毫秒**(`t=0.12s` ⇒ `_t120.png`)。

> 早期版本用 `T` = 抽帧序号(0/1/2),读数会显示成 "0.00 / 0.01 / 0.02",**歧义很坑**。
> 现统一为毫秒;遇到旧目录先确认命名再把 `t/1000` 改回下标。

## 三条判据

| # | 判据 | 失败意味着 |
|---|---|---|
| 0 | 每张 `pixels > 0` | 抽帧没落盘,或图层全透明 (alpha 反解失败) |
| 1 | 同一合成像素数随时序**单调不减**(`--strict-monotonic`) | 入场动画方向反了 / 有元素中途消失。**回弹类方案不要开** |
| 2 | 末帧 `bbox` 在期望 ±`tol` 内 | 位置/尺寸/素材边距错了 |

## 坑

- **别用 md5 判"两张图一样"**:PNG 带时间戳类块,md5 会不同而字节数可能完全相同。**比像素**。
- **背景色要从 manifest 取**,别凭眼睛填。`#0F0F11` 与 `#0E0E10` 差 1 个通道,阈值 6 时不影响,
  但阈值调到 2 就会把整个背景判成内容。
- **阈值默认 6**。半透明边缘像素的差值可能是 1–3,阈值太低会把噪点算成内容。
- 联系表是**给人看的**,不是判据;判据只看上面三条。
